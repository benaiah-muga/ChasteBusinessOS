# Governance

ChasteBusinessOS is in early formation. Governance will evolve with the community.

## Current model (pre-1.0)

- **Maintainers** have merge rights on `main` and set technical direction.
- Significant architectural changes should be proposed via an **ADR**
  (`docs/adr/`) and discussed in a GitHub issue or PR.
- Day-to-day fixes and docs can land via normal PRs with review.

## Decision making

1. Seek consensus among active maintainers.
2. If consensus fails, the designated project lead decides for pre-1.0 velocity,
   documenting the decision in an ADR when it is architectural.
3. Revisit governance before a 1.0 release (consider a small core team charter).

## Becoming a maintainer

Contributors who demonstrate sustained quality work, good judgment on
reliability/security, and respectful collaboration may be invited as
maintainers.

## Conduct

All participants follow the [Code of Conduct](./CODE_OF_CONDUCT.md).
